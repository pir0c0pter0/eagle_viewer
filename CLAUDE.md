# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A web-based viewer for EAGLE PCB board files (`.brd`, which are XML). Pure vanilla JavaScript — no framework, no bundler, no transpilation, no tests. All application code lives in three files: `src/index.html`, `src/index.js`, `src/index.css`. `src/Arduino_MEGA2560_ref.brd` is the sample board loaded on startup.

## Commands

- `npm install` — install Grunt dev dependencies
- `npx grunt` — build (just copies `src/` to `dist/`)
- `npx grunt watch` — rebuild on changes to `src/*`
- `npx grunt publish` — build and deploy `dist/` to GitHub Pages

To run locally, serve the `src/` directory over HTTP (e.g. `python3 -m http.server -d src`) and open `index.html`. A plain `file://` open fails because the page fetches the sample `.brd` via XHR on load.

## Architecture

Everything happens in `src/index.js` (~540 lines), which parses the EAGLE 6.x XML and renders it into the inline `<svg>` in `index.html`:

- **Rendering pipeline** (`loadBoard`): parses `<layers>`, then renders board content into two SVG groups — `#packagesGroup` (hidden, `display: none`) holds one `<g>` per library package as a reusable definition; `#boardGroup` holds the actual board (plain wires/rects/texts, signal wires/polygons/vias) plus `<use>` references that instantiate packages at each `<element>` position with rotation/mirroring.
- **Primitive renderers**: `addWire` (lines, or arc paths when `curve` is set), `addRect`, `addPolygon`, `addVia` (also draws pads via the `actuallyPad` flag, using an even-odd-fill path for the drill hole), `addSmd`, `addText`, `addOrigin`.
- **Layer system**: each SVG element gets a class like `layerN`. Two dynamic `<style>` elements drive appearance: `#styleSheetLayerColors` (generated from each layer's `color` attribute and the fixed 16-entry `LAYER_COLORS` palette) and `#styleSheetLayerVisibility` (regenerated by `setLayerVisible` when sidebar checkboxes toggle, hiding layers with `display: none`). Layers 17/18/23/24 are hardcoded as pad/via/top-origin/bottom-origin.
- **Coordinate system**: EAGLE uses y-up millimeters; SVG is y-down. `#boardGroup` gets a `matrix(s, 0, 0, -s, 0, height*s)` transform to flip the y axis, where `s` is the global `scaleFactor`. Text elements carry their own `scale(1, -1)` to stay readable.
- **Pan/zoom**: mouse handlers (wired inline in `index.html`) pan by moving the absolutely-positioned `<svg>` (`boardOffset`), and `MouseWheelHandler` zooms around the cursor by adjusting `scaleFactor` and rewriting the boardGroup matrix and svg dimensions. State lives in module-level globals (`scaleFactor`, `boardOffset`, `originalBoardSize`, `scrollingTheView`).
- **File loading**: the top-bar file input (`loadFile`) reads a user-supplied `.brd` with `FileReader` and re-runs `loadBoard`, which clears and rebuilds all dynamic DOM.

The code intentionally supports old browsers (ActiveXObject fallback, `attachEvent`, `DOMMouseScroll`) — keep that style in mind when editing.
